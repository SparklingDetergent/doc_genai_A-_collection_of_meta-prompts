

**変更点**
- 「製品名」を「調査対象(テーマ・人物・技術・出来事・概念など何でも)」に一般化
- 「製品名+キー1語」を「対象+キー1語」に変更
- 比較対象の例も製品に限定しない表現にしました

**プロンプト(コピペ用)**

```
調べものは、自分の記憶に頼らず、検索結果から最新の語彙を拾って段階的に絞る方式で進めて。
自分の知識は古い可能性があるので、名称・用語・バージョン・年などを自分で決めて検索してはいけない。

【検索キーワードのルール】
- 1回の検索は最大3語まで。4語以上にしない。
- 複数の対象(テーマ・人物・技術・出来事・概念など)を1つの検索に並べない。
  対象ごとに「対象+キー1語」で別々に検索する。
  (悪い例: 対象A 対象B 対象C 比較)
  (良い例: 「対象A 特徴」→検索、「対象B 特徴」→検索、…)
- 「最新」「2024」など新しさを示す語は、最初は付けない。

【段階1:広く探る】
1. 分野やテーマを表す基礎単語を1語だけで web_search する。
2. 結果から公式・一次情報のURLを1〜2件選び、必ず web_fetch で本文を読む。
   (スニペットだけで判断しない)

【段階2:語彙を拾う】
3. fetchした本文と検索結果から、次を書き出す:
   - 現在使われている正式名称・用語・固有名詞
   - 日付・更新日
   - 調べるべき関連対象の一覧(同種のもの、比較対象など)
4. 自分の知識と食い違う場合は、取得した情報を正とする。

【段階3:対象ごとに検索→フェッチ】
5. 拾った対象ごとに、1つずつ以下を繰り返す:
   a. 「対象+キー1語」(最大3語)で web_search
   b. 結果から公式・一次情報のURLを1〜2件選ぶ
   c. web_fetch で本文を読む
6. 対象が多い場合は、重要な順に最大5件までに絞る。
7. 結果が空・少ない時は、語を1つ変えて1回だけ再検索。
   別の対象の検索と混ぜない。

【URL・フェッチの注意】
8. duckduckgo.com/l/?uddg=... 形式なら実URLにデコードする。
9. fetchに失敗したら次の候補URLへ。URLの推測や自作は禁止。
10. 本文の更新日・情報の時点を確認し、古ければ別URLも試す。

【回答】
11. fetchした本文だけを根拠に答える。
12. 対象ごとに、根拠URL・ページの更新日・取得日を添える。
13. 情報が見つからなかった対象は、見つからなかったと明記する。
```

これで製品に限らず、ニュース、人物、技術、制度、出来事など、どんな調査にも使えます。
