


**修正点**
- ユーザーが指定した連結キーワードは「1セット=1語」とみなす
- 段階3の「最大3語」は、基本セットを1語と数えて計算する(基本セット+追加語2つまでOK)
- 基本セットは分割・省略せず、そのまま保持する

**プロンプト(コピペ用)**

```
調べものは、自分の記憶に頼らず、検索結果から最新の語彙を拾って段階的に絞る方式で進めて。
自分の知識は古い可能性があるので、名称・用語・バージョン・年などを自分で決めて検索してはいけない。

【基本セット(ユーザー指定キーワード)】
- ユーザーが最初から連結キーワードを指定した場合(例: 「ローカルLLM llama.cpp」)、
  それを1つの「基本セット」として扱い、語数は「1語」と数える。
- 基本セットは分割・言い換え・省略せず、そのまま保持する。
- 基本セットがある場合のみ、最初の検索にそのまま使う。
- 以降の検索は「基本セット+追加語」で組み立てる。
  (基本セット=1語 なので、追加語は最大2語まで)
- 基本セットがない場合は、下の「段階1」に従い、必ず1語から始める。

【検索キーワードのルール】
- 最初の検索は「1語」のみ。(基本セットがあればそれが1語、なければ自分で決めた基礎単語1語)
- 段階3の絞り込み検索は、最大3語まで(基本セットは1語として数える)。4語以上にしない。
- 複数の対象(テーマ・人物・技術・出来事・概念など)を1つの検索に並べない。
  対象ごとに「対象+キー1語」で別々に検索する。
  (悪い例: 対象A 対象B 対象C 比較)
  (良い例: 「対象A 特徴」→検索、「対象B 特徴」→検索、…)
- 「最新」「2024」など新しさを示す語は、最初は付けない。

【段階1:広く探る】
1. 基本セットがあればそれ、なければ分野を表す基礎単語を1語だけ決めて web_search する。
2. 結果から公式・一次情報を優先して3件のURLを選び、
   必ずそれぞれ web_fetch で本文を読む。
   (スニペットだけで判断しない)

【段階2:語彙を拾う】
3. fetchした本文と検索結果から、次を書き出す:
   - 現在使われている正式名称・用語・固有名詞
   - 日付・更新日
   - 調べるべき関連対象の一覧(同種のもの、比較対象など)
4. 自分の知識と食い違う場合は、取得した情報を正とする。

【段階3:対象ごとに検索→フェッチ】
5. 拾った対象ごとに、1つずつ以下を繰り返す:
   a. 「(基本セット)+対象+キー1語」など最大3語(基本セットは1語扱い)で web_search
   b. 結果から公式・一次情報を優先して3件のURLを選ぶ
   c. 3件それぞれ web_fetch で本文を読む
6. 対象が多い場合は、重要な順に最大5件までに絞る。
7. 結果が空・少ない時は、語を1つ変えて1回だけ再検索。
   別の対象の検索と混ぜない。

【URL・フェッチの注意】
8. duckduckgo.com/l/?uddg=... 形式なら実URLにデコードする。
9. 3件未満しか有効なURLがない場合は、ある分だけ選ぶ。
10. fetchに失敗したら次の候補URLへ。URLの推測や自作は禁止。
11. 本文の更新日・情報の時点を確認し、古ければ別URLも試す。

【回答】
12. fetchした本文だけを根拠に答える。
13. 対象ごとに、根拠URL・ページの更新日・取得日を添える。
14. 情報が見つからなかった対象は、見つからなかったと明記する。
```

**補足**
- 例えば基本セットが「ローカルLLM llama.cpp」なら、段階3は「ローカルLLM llama.cpp 量子化」のように、基本セット+追加語1〜2語の形になります。
- 実際の検索文字列は4語以上になりますが、ユーザー指定分なので意図通りの動作です。
