4. 維持するagent-node v10.1の基本仕様

以下は原則として変更しない。

4.1 One Turn = One Ticket

通常のユーザー入力とAIの完全な回答を、1つのチケットに保存する。

- 1ターンにつき1チケット。
- ユーザー入力は完全な原文。
- AI回答も完全な原文。
- 要約や省略は禁止。
- プレースホルダーは禁止。
- 大きすぎて保存できない場合は制限エラーとして停止する。

4.2 Immutable Ticket

作成済みチケットは不変とする。

- 上書き禁止。
- 追記禁止。
- 編集禁止。
- リネーム禁止。
- 削除禁止。
- 同一IDの再利用禁止。

不備があれば元ファイルを残し、新しいチケットによる修正・置換関係で対応する。

4.3 Node Identity

- Node IDは2〜4文字の英数字。
- 新しいチャットセッションで一度決定する。
- 同一セッション中は維持する。
- 勝手に変更しない。

4.4 Ticket ID

形式：

"YYYYMMDD-HHMMSS-NodeID"

- 秒単位の精度を必須とする。
- タイムゾーンはAsia/Tokyo。
- 秒精度の時刻を取得できない場合は停止する。
- 推測時刻を使用しない。
- 既存IDとの衝突を確認する。
- グローバルな最新IDは衝突防止にのみ使用する。

4.5 Thread / Branch

以下を維持する。

- thread
- depth
- continues
- supersedes
- related
- derived_from
- HEAD
- Branch
- Root Ticket

スレッド所属は明示的なメタデータと検証済み親子関係で判定する。

ファイルの更新日時や並び順でスレッドを推測しない。

4.6 Concurrency

- Node間は対等。
- ロックを必須にしない。
- 自動マージを行わない。
- 競合を勝手に解決しない。
- 複数HEADが存在する場合は明示的な選択を求める。
- 既存チケットを変更しない。

4.7 Verification

E1〜E4を維持する。

段階| 意味
E1| ファイル操作の成功
E2| ディレクトリ一覧で存在確認
E3| ファイルの読み戻し
E4| 実際の原文との内容比較

E2成功とE4成功を混同しない。

E4を確認できない場合は未確認とする。

4.8 Status Reporting

- 日本語3〜5行。
- 簡潔に報告。
- 成功・失敗・未確認を区別。
- 実際に確認できた事実だけを報告する。

5. PicoClawへの適応方針

PicoClawの仕様に合わせて、必要な部分だけを調整する。

特に以下を確認する。

5.1 Filesystem

- workspaceの取得方法
- Agent_Hubのパス解決
- list_dir
- read_file
- write_file
- edit_file
- append_file
- 読み込み上限
- 分割読み込み
- ファイルの新規作成方法
- 既存ファイルへの上書き防止
- 同時アクセス時の動作

実際に提供されるツールとその仕様を確認する。

ツール名だけを見て機能を推測しない。

5.2 Exclusive File Creation

特に重要。

"write_file" が既存ファイルを上書きする可能性がある場合、immutable ticketの作成にはそのまま使用しない。

以下を区別する。

- ファイルが存在しないことの事前確認
- 排他的な新規作成
- 原子的な作成
- 作成後の一覧確認
- 読み戻し検証

事前確認と書き込みだけで競合防止が保証されると考えてはいけない。

排他的な新規作成を実際に確認できない場合は、その制約を明記する。

5.3 Session

PicoClawの会話履歴とagent-nodeのセッション状態を混同しない。

agent-node側の状態：

- session_node_id
- active_thread_id
- last_own_ticket_id
- active_parent_ticket_id
- active_thread_depth
- session_state_status

Agent_Hubを正本とする。

5.4 Skills

当面は以下の配置を前提とする。

"workspace/skills/agent-node/SKILL.md"

PicoClawのSKILL読み込み仕様を公式資料で確認する。

SKILLの自動選択、手動指定、読み込み範囲、ツール利用可否などを推測しない。

提示形式

- 調査結果

進行ルール

- 毎回、次の対象を明示する。
- 不必要な確認質問をしない。

- 既に調整した箇所を繰り返し書き換えない。
