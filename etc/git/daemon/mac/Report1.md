

# Git daemon 環境 チューニング・見直しポイント（macOS 環境向け・完全版）

現在の検証構成（`git-sandbox`）をベースに、**macOS 環境で本格運用・規模拡大（大人数・巨大リポジトリ・CI 連携）へ移行する場合に「変更を検討するならここ」**という観点を、全 39 項目漏れなくチェックしてまとめた資料です。

---

## 1. 負荷・出力増大（CPU・時間・ディスク容量）の懸念がある項目

### ① 起動スクリプトのログ付与ループ ＋ `--verbose` ＋ `--log-destination=stderr`
- **現在の設定**
  `--verbose` で 1 接続あたり 5〜10 行を `stderr` に出し、`while read` ループ内で外部コマンド `date` を 1 行につき 3〜4 回起動して日時付与・日付ローテーション（月次 `01〜31` / 曜日 `Monday〜Sunday`）を行っています。
- **懸念点**
  - 日付ローテーションによりファイル数自体は増えませんが、**1 日あたりのアクセスが極端に多いと 1 ファイルが大きく肥大化**します。
  - **CI ツールや監視スクリプトが毎秒のように `ls-remote` / `fetch` を叩く環境**では、1 行ごとの `date` プロセス起動が負荷になります。
- **変更を検討するならここ**
  1. スクリプト冒頭で `zmodload zsh/datetime` を読み込み、組み込み関数 `strftime` を使う（外部 `date` プロセス起動ゼロ）。
     ```zsh
     zmodload zsh/datetime
     strftime -s now_day "%d" $EPOCHSECONDS
     strftime -s now_ts "%Y-%m-%d %H:%M:%S" $EPOCHSECONDS
     ```
  2. 通常時の接続ログが不要なら `--verbose` を外し、エラー時のみ記録する。

### ② `transfer.fsckObjects = true`（`etc/gitconfig`）
- **現在の設定**
  `clone` / `push` / `fetch` のたびに、送受信する全オブジェクトの整合性チェック（`fsck`）を実行します。
- **懸念点**
  - 数 GB の巨大リポジトリや数万ファイルの一括 `push` 時に、チェック処理の分だけ転送時間が伸びます。
  - 古い別ツールで作られた「軽微な仕様違反コミット」を含む過去リポジトリを移行 `push` すると、整合性エラーで拒否されることがあります。
- **変更を検討するならここ**
  - 巨大リポジトリの初回移行時だけ一時的に `false` にするか、規模に応じて見直します。

### ③ `--timeout=300`（`git daemon`）
- **現在の設定**
  無通信状態が 300 秒（5 分）続くと接続を切断します。
- **懸念点**
  - 数 GB 級の巨大リポジトリを初回 `clone` する際、サーバー側のデータ圧縮計算（`Compressing objects`）に 5 分以上かかると途中でタイムアウト切断されます。
- **変更を検討するならここ**
  - 巨大リポジトリを扱う場合は `--timeout=900`（15 分）や `--timeout=1800`（30 分）へ延長します。

### ④ `core.logAllRefUpdates = true`（`etc/gitconfig`）
- **現在の設定**
  サーバー側（bare リポジトリ）にも全ブランチの更新履歴（`logs/refs/heads/...`）をすべて記録します。
- **懸念点**
  - 人が使う範囲では数 KB〜数 MB 程度ですが、**CI ツールなどが 1 日に何千回もブランチ作成・削除・`push` を自動実行する環境**では、`logs/` フォルダが少しずつ肥大化します（`git gc` が走らないと古い履歴が残り続けます）。
- **変更を検討するならここ**
  - 大量の自動ブランチ生成を行うサーバーでは、定期的な `git gc` 実行や `false` への変更を検討します。

### ⑤ `--max-connections=64` / `--init-timeout=30`（`git daemon`）
- **現在の設定**
  同時接続上限を 64、接続直後の初期応答待ち上限を 30 秒にしています。
- **懸念点**
  - 大規模 CI で 64 接続を同時に超えると新規接続が待たされる／拒否されます（ただし無制限にするとメモリ不足でサーバーが落ちるのを防ぐ安全弁の役割もあります）。
  - 極めて低速な回線や特殊な中継処理で接続開始に 30 秒以上かかる場合、`--init-timeout=30` で切断されることがあります。
- **変更を検討するならここ**
  - 同時接続数が増える場合は `--max-connections=128` 等へ引き上げます。

## 2. 運用・セキュリティ・互換性上の不都合になり得る項目

| 対象 | 現在の設定 | 懸念・不都合の内容 | 変更を検討するならここ |
|---|---|---|---|
| **`--listen=127.0.0.1`**<br>**`--export-all`**<br>**`--enable=receive-pack`** | 自分 PC 限定、認証なしで全リポジトリ読み書き可 | 他端末からも繋ぐために `--listen=0.0.0.0` や LAN IP に変えると、**同じネットワーク内の誰でも認証なしで全リポジトリの書き換え・削除が可能**になります。 | 他端末へ公開する場合は `git://`（`git daemon`）ではなく、**SSH** や **HTTPS（認証付き）** へ切り替える。 |
| **`--informative-errors`** | 詳細エラーを返却 | 外部公開・セキュリティ重視の環境では、存在しないリポジトリパスを叩かれた際にサーバー内部の構成を推測される材料になります。 | 信頼できる閉域網・検証環境以外では外す。 |
| **`receive.denyDeletes = false`**<br>＋ **`fetch.prune = true`** | サーバー削除許可 ＋ 取得時に手元の追跡参照も削除 | 誰かが誤ってブランチを `--delete` するとサーバーから消え、他のメンバーが `fetch` した瞬間に手元の `origin/ブランチ名` も即座に消えます。 | 誤削除を防ぎたい場合は `receive.denyDeletes = true` に変更する。 |
| **`receive.denyNonFastForwards = true`** | 強制上書き（`push --force`）を拒否 | 安全策として非常に優秀ですが、どうしても過去の履歴を修正して強制上書きしたい作業が発生した際に `push` が弾かれます。 | 原則 `true` 維持（例外時は管理者のみ一時的に解除または別ブランチ運用）。 |
| **`core.symlinks = false`** | シンボリックリンクを通常テキストファイルとして展開 | macOS / Linux 専用のビルド手順等で「シンボリックリンクが OS 上のリンクとして機能すること」を前提にしている場合、動かなくなります。 | Windows クライアントが一切混在しない Mac/Linux 専用環境なら `true` を検討。 |
| **`core.autocrlf = false`**<br>＋ **`.gitattributes (* -text)`** | 改行コードを一切変換しない | Git が自動変換しないため、Windows と Mac の混在チームで各自のエディタが勝手に改行コードを変えると、そのまま差分として記録されます。 | エディタ共通設定（`.editorconfig`）で改行コードを統一する運用にする。 |
| **`safe.directory = *`** | 全ディレクトリの所有者警告を無効化 | 複数ユーザーがログインする共用 Mac で、他人が置いた不正なリポジトリ（`.git/hooks` 等）を誤って触るリスクが上がります。 | 共用 Mac では `*` を外し、信頼できるフォルダだけを個別指定する。 |
| **`core.editor = vi`** | エディタに `vi` を指定 | ターミナルや `vi` に慣れていない作業者がメッセージ無しで `git commit` すると操作に迷うことがあります。 | GUI エディタ（`code --wait` 等）や `nano` への変更を検討。 |
| **`pull.rebase = false`**<br>＋ **`merge.ff = true`** | 分岐時はマージコミット作成、未分岐時は一直線 | 分岐が多いチームでは履歴グラフに `Merge branch ...` コミットが増えます（履歴を常に 1 本の直線にしたい方針とは逆になります）。 | 直線履歴を強制したいチームでは `pull.rebase = true` を検討。 |

## 3. 変更不要（負荷ゼロ・またはむしろ軽くなる設定）の全一覧

以下の項目は、**処理負荷・出力増大・不都合の懸念がなく、そのまま維持して問題ない設定**です：

- **むしろ処理・通信が軽くなる設定**
  - `protocol.version = 2`（不要な参照一覧の送信を省き高速化）
  - `.gitattributes` の拡張子別 `binary` 指定（重い Office・PDF・画像・ZIP 等の差分計算・マージ計算をスキップ）
- **負荷ゼロで安全性・利便性を高める設定**
  - `init.defaultBranch = main` / `core.safecrlf = false` / `core.quotepath = false` / `core.longpaths = true` / `i18n.commitEncoding = utf-8` / `i18n.logOutputEncoding = utf-8` / `gui.encoding = utf-8` / `color.ui = auto` / `push.default = simple` / `push.autoSetupRemote = true` / `user.name` / `user.email`
  - `git daemon`：`--port=9418` / `--reuseaddr` / `--base-path` / `--pid-file` / 末尾ディレクトリ引数
